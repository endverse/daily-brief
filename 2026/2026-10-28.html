🔥 今日重点

同一套 skill，强模型涨 31.1 分、弱模型跌 8.8 分：论文把「skill 适配」做成一个 meta-skill

论文研究 harness 自我进化——不改模型参数、只改 skill 来提升执行——在一个能力区间内是否通用：在 7 个模型、3 个基准上找出 103 组 task-skill 对，同一批 skill 让 GPT-5.6-luna 涨 31.1 分，却让 Gemma-4-E4B 掉 8.8 分。更关键的一条统计是：弱模型失败的 86% 里，被违反的要求本来就写在 skill 文本里——缺的不是知识，是「执行不动」。作者因此提出 skill adaptation：把现有 skill 改写成匹配执行者能力的形式，并把失败诊断（工具执行、上下文管理、指令遵循、验证）蒸馏成一个固定的 meta-skill 来指导改写。用一个外部改写者 Kimi-K3 在不看执行证据的情况下改写 skill，三个弱执行器提升 5.1–14.1 分；把这一步嵌进五轮自我进化循环后，7 个执行器（Gemma-4-E4B 到 Kimi-K2.5）最终分再涨 2.0–5.1 分。结论落在设计建议上：skill 要按执行者能力分层，而不是一套文本通吃。

🔎 新闻要点：样本 = 7 个模型 × 3 个基准，筛出 103 组 task-skill 对；跨度实测 = GPT-5.6-luna +31.1 分 vs Gemma-4-E4B −8.8 分（同一批 skill）；失败归因 = 86% 的弱模型失败违反了 skill 中已写明的要求；方法 = 固定 meta-skill 指导改写（诊断维度：工具执行 / 上下文管理 / 指令遵循 / 验证），改写者用 Kimi-K3、不需要执行证据；单次改写效果 = 三个弱执行器 +5.1~14.1 分；嵌入五轮自进化循环 = 7 个执行器再 +2.0~5.1 分。
🔥 今日重点

kagent v1.0 + Agent Substrate：agent 沙箱变成声明式 K8s 对象，Actor 只在会话期间存在

CNCF 博客给出一套可跑的 agent 沙箱落地路径：kagent 当运行时（CRD + UI），Agent Substrate 当底座，每个 agent 会话跑在独立 Worker（Pod）里的 Actor 中，gVisor 负责软件级隔离（用户态 Sentry 拦截 syscall）、microVM 负责硬件级隔离（直接用硬件虚拟化扩展跑 guest OS）。Helm 装完默认生成 1 个 WorkerPool、2 个 Worker；实测 Substrate 面板显示 0/8、开新会话变 0/9、再开一个 0/10——新会话才起 Actor，会话结束就回收，机制上就是「按会话占资源而非按常驻算力计费」。声明式写法是 kagent.dev/v1alpha3 的 Harness + AgentTemplate：Harness 指定镜像、workerPoolRef 与 snapshotPolicy（会话快照落 gs://），AgentTemplate 定义模型配置与 systemPrompt，可复用到多个 agent。作者强调没有 kagent 时只能 curl 调 Actor，kagent 补的是「声明式 + UI」这一层，隔离与策略执行仍在 Substrate 与 AI Gateway 侧。

🔎 新闻要点：2026-10-26 CNCF 博客；组件 = kagent v1.0（CRD：kagent.dev/v1alpha3 Harness / AgentTemplate）+ Agent Substrate；隔离 = gVisor（Sentry 用户态内核拦截 syscall）+ microVM（硬件虚拟化）；默认 Helm 装出 1 WorkerPool / 2 Worker(Pod)；Actor 按会话起停，面板计数 0/8→0/9→0/10；snapshotPolicy 把会话快照写 gs://；Codex / Claude Code 类 harness 与 langgraph、ADK 的 BYO agent 走同一 Actor 抽象。

Genie 4：首个原生生成音频的实时世界模型，底层换 Gemini 3.8，先给受信测试者

DeepMind 10 月 27 日发布 Genie 4，定位「新一代世界模拟」：它是该系列第一个原生生成音频的实时世界模型，每个世界自带环境声（树林风声、海浪）并支持交互式对话，同时开放实时 steering——跑起来之后还能改场景与物件。模型由 Gemini 3.8 驱动，当前只以 research preview 给受信测试者，随后进 Project Genie 的 AI Ultra 订阅，并开放给 Gemini API 与 AI Studio 的早期合作方。官方没有给分辨率、帧率与单次时长，只描述为「短会话」，与 Genie 3 的 720p/24fps/几分钟相比这几项属于未披露。

能做什么
文本生成可实时探索的 3D 世界：原生合成环境音与对话音频（不是后期配音），支持运行中实时 steering（增删物件、改光照与场景），底层为 Gemini 3.8。分发路径是 Project Genie 订阅 + Gemini API/AI Studio 早期接入。
解决什么痛点
此前的世界模型只有画面没有声音，做具身/机器人仿真时音频线索缺失；「先出视频再改」的流程也无法在运行中试错。原生音频 + 实时 steering 让世界模型更接近可交互的仿真器而非视频生成器。
值不值得
对做具身智能或合成数据的人值得盯：音频 + 可分发生成环境意味着能造带声音的多模态训练场景。但官方未公布帧率、分辨率、单次时长与一致性指标，且仅受信测试者可用，短期无法用于生产；先看 Gemini API 侧的配额与定价再判断。

Gemini Robotics ER 2 上 Google Cloud：机器人「高层大脑」可以直接调云上推理

Gemini Robotics Embodied Reasoning 2（ER 2）在 Google Cloud 上线，定位是机器人的高层大脑：跨形态（从固定机械臂到人形）做空间与时间维度的视频理解、长程规划，并把自然语言指令拆成可执行的动作序列。它属于 Gemini Robotics 2 这套「物理世界智能层」里的推理模型，与底层的 VLA 控制策略分工——ER 2 负责想，VLA 负责动。

能做什么
面向机器人 embodiment 的高层推理模型：读视频做时空理解、做长程任务规划、把指令分解为动作步骤，跨任意形态（机械臂/人形）复用，通过 Google Cloud 提供推理端点。
解决什么痛点
机器人团队过去要为每个任务训专用 VLA，换场景就重训；把「想」的部分抽成一个通用多模态模型后，专用模型只需管低层控制，任务泛化靠 prompt 与规划。
值不值得
公司业务不涉及机器人，属于行业跟踪项：值得知道的是「高层推理与低层控制分离」已经成为具身的主流架构，和大模型应用里「harness + 工具」的分层是同一思路。不必深入。

验证该放在哪一层：17 种 harness 设计横评，独立评审是唯一「又便宜又准」的档

论文把「验证」当成 test-time scaling 的一条独立轴，按介入时机分四层：初始指令、回合中提醒、完成门禁、独立评审。在 7 个前沿编码模型上比 17 种设计，跑 Terminal-Bench（TB）与 SWE-bench Verified（SWE），另建 VisualBench 做视觉/交互产物的专家评测。结论：初始指令与执行中提醒收益温和且依赖模型；完成门禁收益更大但成本显著上升；独立评审（critic）性价比最好——TB 平均涨 5.9–9.5 分、SWE 涨 3.9–6.6 分，成本只到基线的 1.13–1.25 倍与 1.00–1.04 倍。多加评审轮次或换独立 critic 还能再涨最多 3.5 分（TB）；VisualBench 上独立评审的净偏好高出基线 13.2–23.8 分。

能做什么
给出验证设计的可比较坐标系：四层（指令/提醒/门禁/独立评审）× 7 模型 × 17 设计，量化了每层的准确率增益与成本倍数，并指出独立评审在准确率—成本前沿上占优。
解决什么痛点
harness 里「加不加检查、谁来检查」长期靠经验；加门禁常常把 token 成本翻倍而收益不明。这篇把「让另一个 critic 看」与「让同一模型自检」的成本收益分开量化了。
值不值得
做 agent harness 的人值得精读两节：独立评审的成本倍率（1.13–1.25x）与多轮收益递减点。可直接用于决定「自检 vs 外部 critic」的默认配置。限制是基准集中在编码与视觉产物，长周期业务任务未覆盖。

ReGE：把上一次的执行记录压成 guidance，准确率 +9.9pp、构建 token 省 98%

ReGE 把「重试过程中积累的经验」转成下一次的指导：ReGE-Syn 只用一次 coach 调用，就把有界的执行记录与产物合成为自包含 guidance——任务相关发现、建议动作、相关坑，学生模型从原始环境状态起步、按当前观测自行调整。source 生成、合成、执行都用同一个基座模型，不更新参数、不用更强教师。四个基准上准确率平均 +9.9pp（GPT）、+8.8pp（Claude）；对比 adapted AggAgent，guidance 构建 token 省 98.2%（GPT）与 95.5%（Claude），构建+执行总 token 降 15.7% 与 35.4%。

能做什么
单次 coach 调用把「执行记录 + 产物」合成为一份自包含 guidance（发现 / 动作 / 坑），学生模型在同一模型族内直接照做；不需要教师模型、不改参数，适合并行 agent 蜂群的记录汇总。
解决什么痛点
agent 重试时把完整历史塞回上下文，token 随轮次线性膨胀且噪声大；直接摘要又会丢关键步骤。ReGE 证明「压缩成指导」比「搬运历史」更省更准。
值不值得
可直接用于自建 agent 的重试/复盘环节：把失败轨迹压成 guidance 再重跑，而不是把历史全量回灌。限制是四基准以检索/浏览类任务为主，长程工程任务的收益未测；且依赖同一基座模型做 source 与执行。

简单 harness 打败手写 RCA agent：PR@1 65–77% 对 16–53%，规定流程反而跳过决定性证据

论文在 RCAtlas（8 个公开数据集、90 个验证案例）上比较三类「不规定模型怎么调」的简单 harness（单次调用读证据包、SQL agent、Codex 编码 agent）与 5 个已发表的 LLM RCA agent，外加统计与因果方法。结果是简单 harness 最准：三个中端模型上 PR@1 为 65–77%，已发表 agent 只有 16–53%，非 LLM 方法 6–39%。分析指出已发表 agent 把 1/10 到全部模型调用写死成固定阶段与角色，案例显示这些规定会跳过决定性证据；更强的模型主要提升稳定性，多轮 harness 主要提升能力上限，而调高推理档位只改几个点、却把耗时拉到 7 倍。

能做什么
把「手写 SOP 型 agent」与「给模型证据让它自己查」摆到同一数据集上对比，量出 PR@1 差距，并拆开「模型变强 / 多轮 / 高推理档」三种投入的边际收益。
解决什么痛点
故障排查类 agent 普遍被写成固定阶段 + 角色分工，看起来可控，实际把探索路径锁死；换模型也救不回来，因为瓶颈在流程不在模型。
值不值得
做 SRE/排障 agent 的人值得先读结论再动手：先给足证据与工具让模型自由查，再考虑加流程。限制是数据为微服务故障场景（RCAtlas），跨到数据库/网络故障需重测。

CRM-Agent-Bench：555 个有状态任务 + 可执行契约，16 个系统严格成功率 64%–84%

CRM-Agent-Bench 针对「能不能把事办完」而非「答得对不对」：555 个有状态、多轮任务，覆盖 9 个业务域、36 个能力标签，每个任务附一份可执行契约（对动作、参数、顺序、响应、目标状态、受保护状态的检查），成功是契约内全部检查的严格合取，同时报告覆盖率、延迟与成本。16 个系统在审计后的最终版上严格成功率落在 64.32%–83.60%，头部系统分数接近但在成本与分域稳定性上差得很开。

能做什么
用可执行契约替代 LLM 打分：动作/参数/顺序/响应/目标状态/受保护状态逐项检查，把「说对了」和「做对了」分开计分，并输出成本与延迟。
解决什么痛点
企业内 agent 的失败常是「流程走错、状态被改坏」，而现有基准只看最终答案；这类错误在聊天式评测里完全不可见。
值不值得
做企业内部 agent（CRM/工单/审批）时值得借用它的契约写法：为每个任务声明受保护状态与顺序约束。限制是领域集中在 CRM，任务集规模 555，跨行业需自建契约。

自建推理的四个层级：冷前缀首 token 69.4 秒 vs 高复用 2.8 秒，委派给量化小模型并不省钱

一份 7–10 月的自建推理经验报告：作者用 4,165 个编码-agent 网关回合、623 个调试任务与三组带隐藏行为检查的委派实验，比较 vLLM、SGLang、llama.cpp、MLX 上的开源权重模型。最刺眼的数字是冷前缀请求首 token 中位 69.4 秒，高复用请求 2.8 秒——同一套服务，缓存命中与否差 25 倍。委派实验里直连编码 15/15 全过，委派给量化 Qwen3-Coder 30B-A3B 的 worker 是 12/15 与 14/15；另一套 15 题固定产物契约上直连 45/45、Nemotron Cascade 2 worker 12/45、Qwen3-Coder worker 0/45。结论是「能出文本、能调工具、能过独立行为检查」是三个不同层级，而且直连前沿模型在「每成功一次的成本」上反而更低。

能做什么
用真实会话数据（4,165 回合 / 623 调试任务 / 3 组带隐藏检查的委派实验）量化自建服务的关键指标：冷热前缀的 TTFT 差、量化 worker 的通过率、以及「每验证成功一次」的等价比成本。
解决什么痛点
「开源自建省钱」的常见假设忽略了冷启动、工具调用格式差异与缓存复用率；报告显示量化小模型在严格产物契约下会直接归零（0/45）。
值不值得
打算自建 vLLM/SGLang 服务的人值得读两节：前缀缓存命中率对 TTFT 的影响、以及委派前必须先做隐藏行为检查。限制是单作者环境、模型版本集中在其测试期，结论不能直接外推。
