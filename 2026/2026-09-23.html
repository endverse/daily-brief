🔥 今日重点

Agent Harness 成研究焦点：RRSI 让 agent 外壳递归自改进

RRSI 把 agent 的 harness（提示、控制流、工具、记忆、上下文管理）当作可迭代优化的对象，通过逐组件提议-选择实现系统级递归自改进（RSI），并加正则化对抗只记住训练任务的过拟合。同期 Harness-Zero 研究把领域最优 harness 蒸馏进模型本身。

论文指出纯 RSI 会在训练任务上过拟合、泛化差，RRSI 用正则化约束递归进化；Harness-Zero 针对「最优 harness 因领域/实例/模型而异，通用 agent 只能用次优共享外壳或路由到越来越多专用外壳」的困境，走蒸馏路线。国内 QCon/云栖也在讲快手电商导购的 Harness Loop 实践。

Simon Willison：MCP 从来是坏主意？——它的真实价值在哪

针对「MCP 是坏主意」的观点反驳：跑全权限终端 agent（Claude Code、Codex 等）时确实可直接调 API、不需要 MCP；但当你想要更受控——精确限定可访问的外部服务、统一处理鉴权——时，MCP 的价值就体现出来了。

能做什么
厘清 MCP 的适用边界：受控访问、权限收敛、统一鉴权场景下有价值，全权限 YOLO agent 场景下可省略。
解决什么痛点
社区对 MCP 该不该用争论不休，缺乏「什么场景值得引入」的清晰判据。
值不值得
做 agent 工具接入选型时值得一读，帮你判断团队场景要不要上 MCP；观点文，无代码。

Jev：System One 决策模型——LLM 的新形态

TypeSafe AI 发布 Jev，接受文本输入但不输出文本，而是返回对应分类/是否问题/评分的浮点数及置信度，被称为「System One 模型」（Simon 更认同「决策模型」的叫法）。

能做什么
输入非结构化状态（diff、trace、日志）+结构化问题，一次前向就返回校准过的概率分布，而非生成文本。
解决什么痛点

值不值得
值得留意的新范式——把 agent 里的「快决策」从生成式 LLM 剥离出来降本提速；生态刚起步（已有 llm-typesafe 插件），可观望。

Kubernetes v1.37：追踪 PVC 上次被使用时间（Beta）

v1.37 将 PersistentVolumeClaimUnusedSinceTime 特性门控提升为 Beta（默认开启）。PVC 保护控制器会为每个 PVC 加上 Unused 条件，直接告诉你当前是否有运行中的 Pod 引用它，无需自定义工具或交叉比对。

能做什么
为每个 PVC 添加 Unused 条件并记录上次被使用时间，原生标识出无 Pod 引用的存储卷。
解决什么痛点
以往判断 PVC 是否闲置需自写工具交叉比对 Pod 引用，难以做存储清理与成本回收。
值不值得
直接相关——你负责集群存储方案，这是原生的闲置卷识别能力，做存储治理/降本时值得启用；Beta 默认开启，可直接用。

AKS Flex Nodes 公开预览：混合/边缘节点接入 AKS 控制面

Flex Nodes for AKS 让应用和平台团队把混合与边缘基础设施作为连接的 worker 节点接入 Azure 上的 AKS 控制面，在边缘保持一致的 Kubernetes 控制面体验。目前为公开预览。

能做什么
把本地/边缘机器作为 worker 节点挂到云上 AKS 控制面，统一用一套 K8s 控制面管理混合与边缘算力。
解决什么痛点
混合/边缘场景下控制面分散、管理体验不一致，难以统一纳管。
值不值得
若有边缘/混合部署诉求可关注这一托管控制面思路；预览阶段、绑定 Azure，自建集群参考价值有限。
