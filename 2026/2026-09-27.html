🔥 今日重点

GKE Agent Sandbox：把 agent 代码执行隔离沉到 K8s 层，官方称降本 75%

Google Cloud 发布 GKE Agent Sandbox，用开源 gVisor 的用户态内核（Sentry）为 LLM 生成的不可信代码做内核级隔离，配合 warm pool 预热池把冷启动压到亚秒级，官方称相较常驻沙箱可省约 75% 成本。背后开源项目落在 kubernetes-sigs/agent-sandbox，把「一个 agent 会话对应一个隔离沙箱」做成 K8s 原生能力。

隔离后端可选 gVisor（用户态内核拦截系统调用）或 Kata Containers（轻量虚拟机）；warm pool 通过预热空闲 pod 消除按需创建的冷启动延迟；成本节省来自沙箱可随会话空闲快速回收，而非常驻占用资源。
🔥 今日重点

Anthropic 生命科学实验室：Claude agent 发现类 CRISPR 的新酶系统

Anthropic 成立生命科学研究组与实验室，用 Claude 挖掘 DNA 数据集识别未表征蛋白家族、批量生成假设并在实验室验证。9 月 23 日公布早期结果：在科学家仅给高层方向的情况下，Claude 发现了一个功能尚未知、性质类似 CRISPR 的全新酶系统。

限制酶、Taq 聚合酶等改变生物学的发现都始于在分子多样性中『注意到异常』；此次由 agent 在最小人工干预下完成假设生成到实验验证的闭环，新酶功能仍待进一步确证。

kubernetes-sigs/agent-sandbox：SIG-Apps 的 agent 沙箱标准

Google 在 KubeCon 推动、落在 SIG-Apps 的开源项目，提供 Sandbox CRD 与控制器，声明式管理隔离、有状态、单例的 agent pod，后端可插 gVisor 或 Kata Containers。它把「一个会话一个隔离沙箱」变成 K8s 原生一等资源，正是 GKE Agent Sandbox 背后的开源内核。

能做什么
定义 Sandbox 自定义资源与控制器，在任意 K8s 集群上声明式拉起/回收隔离的 agent pod，隔离后端 gVisor / Kata 可选，支持 warm pool。
解决什么痛点
各家 agent 平台各造一套沙箱、隔离与生命周期无标准；此项目把它标准化到 K8s API 层，可自托管不锁定云厂商。
值不值得
你想在自有 K8s 上做多用户 agent 沙箱多路复用+空闲挂起，这是可直接评估的开源底座，比 Daytona 更贴 K8s 原生。看清成熟度与 KEP 进度即可决定要不要跟。

Kubernetes 为何需要一套 agent 执行新标准

Google 开源博客论证：自主 agent 大量生成并执行代码时，K8s 需要统一的 agent 执行标准。该标准在设计上同时支持 gVisor 与 Kata Containers 两种隔离后端，让团队按安全/性能权衡自选，而非绑死单一技术。

能做什么

解决什么痛点
回答『为什么容器不够、为什么需要在 K8s 层立标准』这个前置问题，是理解 agent-sandbox 项目动机的背景文。
值不值得
偏理念但信息密度高，读一遍能建立对 agent 沙箱在 K8s 落位的整体判断，配合上面两条食用。

AlloyDB 推出「面向 agent 的 PostgreSQL」：为 agent 突发查询做工作负载隔离

Google 宣布 AlloyDB PostgreSQL for agents（预览），通过为 agent 动态供给 sandboxed 数据库实例，隔离 agent 密集推理循环带来的突发查询，避免拖垮承载核心业务的主库，实现实时数据访问不影响关键系统。

能做什么
在 AlloyDB 上为 agent 突发流量动态分配隔离的数据库实例（sandboxed instances），把 agent 的高并发不可预测查询与 OLTP 主库负载物理隔开。
解决什么痛点
几个 agent 同时跑密集推理循环就能用查询风暴打垮传统架构；隔离实例保住系统级 SLA。
值不值得
金融量化对主库稳定性极敏感，这是 agent 接入生产数据库的一类解法参考；托管预览、绑 AlloyDB，自建栈仅作架构借鉴。
