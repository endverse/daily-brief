🔥 今日重点

谷歌开源 AX：K8s 风格的声明式 Agent 编排器，亚秒级挂起/恢复 + Actor 多路复用

谷歌开源 AX（Apache 2.0，代码在 google/ax、文档站 agentexecutor.io），一个跑在 Agent Substrate 运行时之上的声明式编排器，把 agent 会话当作有状态 Actor，而不是微服务或批处理任务。控制面在 ax.io/v1alpha1 API 组下给出四类原语：Task 定义执行生命周期与沙箱资源约束，Workspace 在任务启动前装配环境（声明式挂载 Git 仓库、配置 MCP 服务器、安装技能包，或由初始化 agent 按自然语言执行），Gateway 把沙箱出网限制在主机名与端口白名单内并向出站请求注入凭据，Model 统一管理 LLM 参数、运行时配置与存在 Kubernetes 里的密钥。空闲时（等模型、等工具、等人）它把执行状态做检查点后挂起，恢复是亚秒级且无冷启动，并把数十个隔离 Actor 复用在同一批共享主机工作进程上。操作面是一个 Go 写的 ax CLI：ax apply 注册清单、ax watch 流式看任务阶段、ax ssh 进沙箱调试、ax suspend/resume 手动控制；控制面用 ko 部署到 Kubernetes，Redis 放在 ax-system 命名空间，复用现有 kubeconfig。Hacker News 上评价分化：infra 工程师认可它消掉了 agent 等待期的高昂云成本，质疑者指出 ko + 自定义 CRD + 容器 registry 带来的运维负担，也有系统与安全从业者强调 gVisor 隔离沙箱、出站代理连接中断与基础密钥管理这些早期问题。它的定位是底层执行运行时，而不是 LangGraph/CrewAI 那类高层应用编排框架。

🔥 今日重点

DeepSeek 公开 V4 训练沙箱底座 DSec：可组合环境层 + 按需镜像加载，生产超卖超 50 倍

DeepSeek 联合清华大学发布技术报告《DeepSeek 弹性计算（DSec）：面向大规模智能体训练的高效沙箱基础设施》，首次公开支撑 DeepSeek-V4 全部训练、评测与数据预处理流程的沙箱底座，作者团队超 130 人，梁文锋在列。DSec 同时支持 FnCall、Container、MicroVM、Full VM 四种执行后端，用统一 Python SDK（libdsec）按任务选隔离强度：FnCall 复用预热容器跑在线评测等短任务，Container 服务最通用的软件工程与工具调用，MicroVM 提供更强隔离边界给安全任务，Full VM 支持图形界面、渲染与 Android 场景。环境被拆为基础镜像、工作区、工具包三层各自独立版本管理，以 EROFS 格式存储、运行时用 OverlayFS 按需组合；生产某一周用到 11,266 个基础镜像、102,171 个工作区，工具包更新时只需重建变化的那一层。因为实测沙箱运行实际访问的数据只占镜像总大小的 4.2%–13.3%，镜像数据放 3FS、本地只拉元数据：集中创建 8,192 个容器的完成时间从 60 多分钟压到约 35 分钟（加速约 1.71x，磁盘写入降约 57%），工作区从逐个解压 tar.gz 改为直接挂载 EROFS 层后从 79 分钟降到 45 分钟、写入量降到约 1/5.5。资源侧约 90% 的沙箱平均 CPU 用量不超过申请量的 5%、内存却要长期驻留，DSec 用 virtio-pmem 与 DAX 让同宿主机 MicroVM 共享宿主页缓存（峰值内存较基线降 40.2%），叠加 DAMON 与 balloon 空闲页回收（按时间累计内存消耗降 21.2%），把生产超卖率做到 50 倍以上。

Google Data Agent Kit 转 GA：把数据工程最佳实践做成 skill 包，塞进任意 coding agent

Google Cloud 的 Data Agent Kit 正式 GA，它以「skill 包 + MCP 工具」的形式把 Google 工程师的数据最佳实践交给 agent：bigquery-graph-author 会把表映射成节点与边、逐个校验候选关系再让你确认，bigquery-graph-query 负责写 GQL；bigtable-basics 按读取方式设计 row key 并提前标出热点与全表扫描；federate-lakehouse-catalog 让 agent 直接查 AWS Glue 与 Databricks Unity Catalog 里的 Iceberg 表，不用先建摄取管道。接入面很宽：VS Code/Antigravity/Cursor 等编辑器的 IDE 扩展，Antigravity 2.0、Antigravity CLI、Claude Code、Codex 的插件，以及预装的 Cloud Shell 与 Cloud Workstations。GA 新增 BigQuery Graph、Bigtable 进入支持范围，以及用 Managed Service for Apache Spark 跑 Lakehouse 表（serverless、会话级状态保留、支持 Iceberg 分支/时间旅行/模式演进），还有把 dbt/Dataform 模型与 notebook 一起编排成 Airflow 上的 Orchestration Pipeline。所有步骤都跑在用户自己的 IAM 权限下。

能做什么
把数据云的用法沉淀成可被第三方 coding agent 加载的 skill 集合（bigquery-graph-author / bigquery-graph-query / bigtable-basics / federate-lakehouse-catalog / gcp-pipeline-orchestration），配合 MCP 工具执行；支持 IDE 扩展、Claude Code/Codex 插件、Cloud Shell 三种接入方式；GA 新增 BigQuery Graph、Bigtable、Spark 上的 Iceberg 查询与 Airflow 编排。
解决什么痛点
企业里让 agent 碰数据层最怕「照着常见写法乱写」：property graph 要手写 CREATE PROPERTY GRAPH DDL、Bigtable 行键设计错就出热点、跨云表要先建摄取管道、分析逻辑要手工搬成 Airflow 任务——这些领域知识此前只存在于文档和资深工程师脑子里。
值不值得
值得看的是它的封装形态而非 Google 专属内容：把领域最佳实践按 skill 粒度拆分、每个 skill 带校验与确认步骤、全部走调用者 IAM，这套模式与你做 skill 沉淀的路线一致，可以直接借鉴结构；实际使用前提是数据在 Google Cloud 上。

DeepSeek 开源昇腾基础组件：算子库 + 通信库对上 GPU 侧的那套，实测通信接近硬件上限

DeepSeek 开源面向华为昇腾的基础设施组件，涵盖 TileLang 高级语言编译工具、高性能计算库与分布式通信库，与之前面向 GPU 开源的组件一一对应：算子侧发布 DeepGEMM、FlashMLA、TileKernel、DeepSelect，通信侧是 DeepEP。昇腾提供 Ascend C API 与 PTO ISA 底层指令体系，既支持手工调优也支持 TileLang 这类高级语言编译对接。基于 UBL128 超节点，DeepEP 覆盖 EP/CP/PP/FSDP 通信算子，实测 Dispatch 375 GB/s、Combine 347 GB/s，官方称接近硬件上限；部署侧给出 V4.1-Flash 在 EP32 下的 offline 纯模型数据：TPOT=5ms 时每卡输出 2,469 tokens/s，TPOT=10ms 时 5,102 tokens/s。华为同步把成果在 CANN 社区开源，包含大 EP 低时延推理、单卡/单机部署、大规模训练、超长文本 KV cache 池化与 Agentic RL。

值不值得
