🔥 今日重点

Agent Substrate 1.0 上 GKE：空闲会话 500ms 挂起，密度 10 倍于容器

Google 把 Agent Substrate、gVisor、OpenRL 一起捐给 CNCF，并宣布 Agent Substrate 1.0 与 GKE 上的托管 GA。它把有状态的 Actor（内存、文件、身份）与可复用的 Worker 热池拆开，agent 空闲时快照落盘并归还 Worker，下次请求 500ms 内恢复，官方称达到标准容器 10 倍密度、每秒 500 次以上挂起/恢复。隔离层可选 Cloud Hypervisor microVM 或 gVisor，跑标准 OCI 容器；配套的 OpenRL 用 DRA 分加速器、靠 llm-d 做前缀感知路由与 GPU 时间片跑 RL 后训练。这是把「每个 agent 一个 Pod 会一直占着 CPU/内存」这个问题在调度层直接解掉的方案。

Google 把 Agent Substrate、gVisor、OpenRL 三个项目捐给 CNCF（上月已进 CNCF Sandbox，gVisor 走向 Incubation），同时宣布 Agent Substrate 达到 1.0 并作为 GKE 托管能力 GA。架构上把状态与计算拆开：Actor 持有每个 agent 的内存、文件与独立身份，Worker 是从热池里取的可复用执行沙箱，Gateway 按 Actor 身份做进出向访问控制并注入密钥。agent 停下等模型回复或工具调用时，系统把内存与文件快照到存储、立刻归还 Worker，下次请求在 500ms 内恢复到任意空闲 Worker。公布的指标：标准容器 10 倍的密度、每秒 500 次以上 suspend/resume、100 多个贡献者；隔离可选 Cloud Hypervisor microVM 或 gVisor，直接跑标准 OCI 容器。OpenRL 用 Kubernetes DRA 切分加速器池，配 llm-d 做前缀感知的 rollout 路由与训练/采样之间的 GPU 时间片，支撑 RL 后训练的多轮 rollout。早期设计伙伴里有 Nous Research（在它上面做 Hermes Enterprise），kagent 也已在用。
🔥 今日重点

LoopForge 开源：腾讯轻量云的云端自进化研发平台，内部 20+ 业务月交付 200+ 需求

腾讯轻量云开源了 LoopForge，一套云端自进化研发平台，内部 20+ 业务在用、单月自动完成 200+ 需求与单据。核心取舍是「一个共享会话只绑一个云端工作区、只有一个 Main Bot」：产品/设计/研发进同一会话，换人发言自动续接上下文，写操作按三挡权限由独立审查模型代批常规命令。往上叠五层 SOP（节点内置编译、单测、规范门禁，不通过不放行）与定时 Issue 流水线（自动拉单、并行修复、冲突回退到 SOP 节点自解、审批挂起即释放资源），最外层用工程级 RSI 把每次运行的复盘结果写成 SOP 与角色资产的改进处方，人一键应用。

腾讯轻量云开源 LoopForge（github.com/Tencent/LoopForge），已在内部 20+ 业务落地，单月自动完成 200+ 需求与日常单据。演进分五步：① 把工作区搬上云端——每任务一个隔离容器/沙箱，可同时拉多个仓库并切分支，存算分离、自有机器可接入，闲置自动快照休眠；② 一个共享会话只绑一个云端工作区、只有一个 Main Bot 对接全组，成员换人发言自动续接同一上下文，写操作按三挡权限模式放行（独立审查模型代批常规命令，越界或高危才找人）；③ 把岗位能力与工程规范拆成五层 SOP，节点内置编译/单测/规范门禁，不通过不放行，人可按节点接管；④ 定时巡检拉单、并行修复、冲突自动回退到 SOP 节点自解、审批挂起的单子即时释放后台资源；⑤ 工程级 RSI——每次 SOP 跑完由复盘引擎回溯轨迹给出 0-100 健康度并生成结构化改进处方，人一键应用改写 SOP 与角色资产。

skill 评测五条铁律：Δ=0 时九成是 skill 根本没被加载

Google Cloud 用配对消融（同一任务、同一沙箱，A 臂不挂 skill、B 臂挂）评估自家 Developer Plugin：Δ=0 的九成原因是 agent 压根没加载 skill——路由只看 frontmatter 的 name/description，skill 超过十几个后会出现欠触发与“兄弟劫持”（相邻 skill 的宽泛描述先截走 prompt）。他们开源 skill-reach（lint / overlap / eval / optimize），用词表重叠度找最近竞争 skill（示例 0.69）并跨 Claude Code、Antigravity、Codex 做路由探测。另两条硬结论：开发机上跑基准会被缓存的云凭据、导出的项目变量与 CPU 负载污染；同一份代码同一 prompt 连跑，超过三分之一的任务分数会变。AlphaEvolve 搜索里还出现四种 reward hacking，因为 0.95 正确性 + 0.05 token 效率的合成分数让“不花 token 直接读答案文件”占优。

能做什么
配对 WITH/WITHOUT 消融 + 跨 harness 路由探测 + 词表重叠检测；把正确性、可发现性、效率、效果、安全五个维度做成正交分，禁止用 token 节省抵掉失败或违规。
解决什么痛点
skill 越堆越多后互相抢触发、正文塞满公共 API 文档，既烧 token 又不涨分；单次跑通的“绿勾”评测无法区分是 skill 起效还是环境兜底。
值不值得
对维护 skill 库的人，这五条可直接当验收清单，skill-reach 也能立刻跑；限制是它主要覆盖云厂商类任务，业务私域 skill 的判分集仍要自己建。

能做什么

Agent Substrate 1.0 + GKE GA：Actor/Worker 拆分的 agent 运行时进 CNCF

Agent Substrate 达到 1.0 并作为 GKE 托管能力 GA，同时与 gVisor、OpenRL 一起捐给 CNCF。Actor 持有 agent 的内存、文件与身份，Worker 是从热池取的可复用沙箱，Gateway 按身份注入密钥并做访问控制；空闲时快照落盘、归还 Worker，恢复时延 500ms 以内。官方数字：标准容器 10 倍密度、每秒 500+ 次挂起恢复、100+ 贡献者；隔离可选 Cloud Hypervisor microVM 或 gVisor，跑标准 OCI 容器。

能做什么
