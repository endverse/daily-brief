🔥 今日重点

Google 的 Agent Substrate 在 GKE 开放可用：10 倍密度承载百万级 agent 沙箱，sub-500ms 恢复

Google 宣布 Agent Substrate 在 GKE 上可用：这是一个开源、默认安全的 agent 执行运行时，官方称相比标准容器运行时密度高 10 倍、可跑百万级沙箱，恢复操作 sub-500ms、每秒 500+ suspend/resume，并内置零信任内核与网络隔离。它的核心是“把 agent 执行与机器管理解耦”：Kubernetes 继续管机器（节点自愈、集群弹性伸缩），一个新执行层直接在本地 worker 上做高频挂起/恢复，从而绕过标准 K8s 控制面的瓶颈。隔离用硬件隔离的 Cloud Hypervisor microVM 或 gVisor 沙箱，配合出口代理在 agent 触及不到的位置注入凭据。Google 点名 Nous Research（Hermes Agent 团队）已在 Agent Substrate 上构建。

关键事实：10× 密度、百万级沙箱、sub-500ms resume、500+ suspend/resume/秒；支持 Axion Arm 处理器（官方称沙箱负载性价比高 30%）；可跑在任何 Kubernetes 上、针对 GKE 优化；与 Agent Sandbox、内核隔离 Pod 并存。
🔥 今日重点

openJiuwen 发布并开源企业级 AgentOS：蜂群协同 + 自演进 + 算力亲和，讲究工程护城河

由华为 2012 实验室、华为云、终端等团队联合高校与开发者共建的开源 AI Agent 平台 openJiuwen，发布并开源了企业级 AgentOS，把多智能体协同、自演进、算力亲和与企业级安全可靠整合进统一底座，并以插件化架构连接上层应用与底层模型/算力。协同侧走“蜂群协同 + 工作流编排”，支持任务拆解、角色分工、并行执行与关键环节人工介入；自演进侧依托执行轨迹、用户反馈与记忆，把有效经验沉淀为可复用能力。运行底座提供多租户隔离、安全沙箱、权限管理与安全护栏，并以故障恢复支撑长任务高可靠运行；北向生态把技能/连接器/插件/专家/专家团五类资产通过 Agentic Hub 发布共享。

关键事实：面向企业规模化落地的开源 AgentOS；架构分 Agent System Service / Agent Distributed Runtime / Agent Framework 三层；华为在 HC2026 发布基于它的“一体机开源 Agent 加速平台”，称可实现小时级端到端私有化部署；社区项目称已在 30+ 行业伙伴商用落地。

Asana 靠“保持缓存完整”把浏览器 Agent 单次成本砍到 1/76：144 次实测 $36.21 → $0.47

Asana 做了 144 次跑的实测：在 GPT-6.1 Sol 上优化后的工作流单次估算模型成本 $0.47、约 4 分钟，比原生产设置（Model B）便宜 76 倍、快 5 倍。关键手段是“保住 prompt cache”——89% 的输入命中缓存、按未缓存价的 5% 计费，仅这一项把单次成本从 $1.97 降到 $0.47（4 倍）；同时重做了截图策略与历史预算。在 Model B 上最佳条件也把单次成本从 ≥$36.21 降到 $1.24（29 倍）。

能做什么
通过稳定 prompt 前缀、调整截图策略与历史预算来维持 cache 命中，把浏览器 agent 的单次成本压到 1/76，且不牺牲任务正确率（全部通过并命中 192 个事实）。
解决什么痛点
浏览器/computer-use agent 上下文长、重复前缀多，缓存一旦失效成本剧增；团队常误以为要换更便宜的模型，其实是工程配置问题。
值不值得
对你做 agent 成本治理直接可用——把“保持缓存完整”当成一等设计约束，比换模型更见效；结论来自厂商客户实测，注意它针对特定工作流。

Red Hat 把 Kueue 1.4 与 DRA 打通：共享 GPU 配额可按显存精确核算

Red Hat 介绍 Kueue 1.4 如何与 Dynamic Resource Allocation（DRA）集成：DRA 已在 Kubernetes 1.34 GA，能按真实设备属性（显存、算力、拓扑）匹配需求，但它只管发现与分配，不管配额、公平与抢占——Kueue 补上这块，把配额强制、借用、抢占与准入公平共享带进 DRA 管理的设备。传统 device plugin 把 GPU 当“匿名整数”（nvidia.com/gpu:1），80GB 整卡与 5GB 切片都记“1”，无法精确核算；DRA+Kueue 可按 DeviceClass 做整卡或显存级配额。Red Hat build of Kueue 1.4 的 operator 会自动探测集群 DRA 能力并开启对应 feature gate。

能做什么
把 DRA 暴露的真实设备属性纳入 Kueue 的配额与公平调度：管理员用 deviceClassMappings 把 DeviceClass 映射为逻辑配额资源，即可按整卡或显存切片做配额、借用、抢占与准入公平共享。
解决什么痛点
device plugin 把 GPU 当匿名整数，整卡与切片都记 1，多租户共享 GPU 时无法准确核算、也就无法公平；训练团队与推理团队会互相挤占。
值不值得
这是你“K8s 集群建设 + GPU 多租户”最直接可用的技术点：DRA 已是 1.34 GA 能力，Kueue 补齐配额层，值得在生产前纳入选型评估；注意 Kueue+DRA 的 feature gate 仍在演进。
