🔥 今日重点

微软开源 TauGrid，把 Kubernetes 上的 AI 工作负载管理打包成一个平台

TauGrid 是微软新开源的云原生 AI 工作负载平台，基于 Kubernetes 构建，覆盖数据准备、训练、微调到推理的全生命周期 GPU 任务管理。它把 Kueue（队列调度）、KubeRay（分布式训练）、GPU 健康监控与可观测性统一集成，通过 Helm 一键部署，目标是消除自己拼装多组件、写胶水代码的活。

对工程团队提供工作区、队列、计算配置等抽象；对研究人员屏蔽 K8s 复杂度，用 CLI 直接提交任务。作者 Sergio De Simone，2026-09-20 发布。
🔥 今日重点

APUS 开源国内首批「决策模型」复现 fast-browser-use，本地模型秒级决策、零 API 费用

APUS AI 实验室开源了针对 Jev「决策模型」范式的独立复现，封装成开箱即用的 Agent Skill fast-browser-use。核心机制是跳过自回归解码、用单 Token Logits 直接对候选动作打分，由本地 Qwen3.5-9B 完成『点哪里、选哪个』。实测在 Apple M2 Pro 上全程离线跑真实维基检索中位约 18 秒、表单填报约 3 秒，单任务仅打分 4 次，零云端调用、零 API 费用，MIT 协议。

决策模型面向 agent 最高频的分类/选择/评分/真伪判断需求，直接返回类型化答案与置信概率而非逐字生成，验证了『大模型慢规划 + 轻量模型快判断』的 Harness 分工。已封装为标准 Skill，一行命令接入 Claude Code / Codex / OpenCode。项目地址 https://github.com/APUS-AI-Lab/fast-browser-use。

When EOS Tokens Disagree：on-policy 蒸馏里的长度膨胀根因

研究 on-policy 蒸馏（OPD）中学生模型回复越来越长甚至耗尽生成预算的问题，定位到根因是学生与教师模型的终止 token 不匹配。在 Qwen3、Llama、Gemma 上，即便声明的停止集合相同，两个模型也可能把停止概率放在不同的 EOS token 上。94 upvotes。

能做什么
指出并诊断 OPD 长度膨胀的机制性根因——终止 token 失配会压制学生偏好的终止行为，给出跨三大开源模型族的证据。
解决什么痛点
蒸馏后模型输出冗长、吃满生成预算，推理成本上升，此前多被当成调参问题而非机制问题。
值不值得
对做模型训练/蒸馏的团队有直接参考价值；对你以基础设施为主的方向属于背景知识，了解结论即可。
