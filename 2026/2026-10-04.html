Cloudflare 开源 cloudflare-os：把内部全员在用的 AI 生产力环境做成一套「操作系统」

别再给 Agent 一个「毛坯房」：把既有研发环境翻成 Agent 可用的 ADE（QCon 上海）

蚂蚁集团 Agent 工程师李俊将在 QCon 上海（10/22–24）分享《别再给 Agent 一个「毛坯房」了》。核心观察是：AI Coding 把个人写码效率抬高后，整条链路仍卡在联调——环境搭不齐、流量跑不准、问题查不清、环境养不住；他借阿姆达尔定律指出生码只占链路一部分，环境与验证才是新瓶颈。方案是把既有 DEV/Stable 研发环境「上翻」为 Agent 可用的 AI 研发环境（ADE）：以沙箱提供可日抛的执行面，以 Artifact FS 统一上下文与产物，以 Agent 友好终端提供可观测、可编排的行动语言。分享还覆盖从「给人用的 1.0–3.0」到「给 Agent 用」的选型取舍、踩坑与可量化收益，以及人机协同边界如何划。

要点：①瓶颈从「写码」转到「环境与验证」（借阿姆达尔定律说明）；②ADE 三件套＝可日抛沙箱执行面 + Artifact FS 统一上下文/产物 + Agent 友好终端；③讲清「给人用的环境」如何翻成「给 agent 用」及其踩坑；④含可量化收益与人机协同边界。

claude-mem：给编码 agent 加跨会话持久记忆，兼容 Claude Code / Codex / Gemini 等

thedotmack/claude-mem 是一个开源的 agent 记忆层：它捕获 agent 在一次会话中的全部操作，用 AI 压缩成记忆，再把相关内容注入未来会话，让 agent 跨会话保留上下文。官方称支持 Claude Code、OpenClaw、Codex、Gemini、Hermes、Copilot、OpenCode 等多种 agent。它针对的是每次新会话 agent 都从零开始、重复摸索同一代码库与工作流的问题，属于「给现成 agent 补记忆」的轻量插件式工具。

能做什么
捕获会话操作 → AI 压缩 → 注入后续会话，为多种编码 agent 提供跨会话持久记忆（Claude Code / Codex / Gemini / Hermes / Copilot 等）。
解决什么痛点
agent 每次新会话都「失忆」，重复探查同一仓库与流程，浪费 token 与时间。
值不值得
长期用编码 agent 的可以直接试；记忆压缩的质量与隐私（操作会被本地/上传存储）需自评。

LoopCD：几乎零成本地「解码」循环 Transformer

循环 Transformer 通过反复执行同一共享块实现参数高效，每次循环都会产生一个可解码同一 next token 的中间表示，但标准解码丢弃了较早循环的状态。论文利用「早循环计算更少」这一特性天然得到对齐的弱-强预测对，提出免训练的对比解码框架 LoopCD，用弱预测引导 token 选择，几乎零额外成本地提升解码质量。

能做什么
免训练对比解码框架 LoopCD：利用循环 Transformer 自身早/晚循环的弱-强预测对，引导 token 选择。
解决什么痛点
标准解码丢弃了循环中间状态，没利用「早循环＝弱预测」这一免费信号。
值不值得
用循环 / 参数高效架构做推理优化的值得关注；需在具体模型上验证收益。

企业级 Agent Infra 架构实践：K8s Agent Sandbox + OVN-Kubernetes + Istio 做 Agent 运行时隔离（QCon 上海）

上汽集团云计算中心架构师将在 QCon 上海分享《企业级 Agent Infra 架构实践：从安全沙箱到网络管控与身份治理》。他指出 Agent 应用正从「生成内容」走向「自主执行」——运行模型生成的代码、操作浏览器、调用 MCP Tool 与内部业务系统，企业级 Agent Infra 因此面临四重矛盾：运行时隔离要求高（要同时保证文件系统与内核隔离，传统容器隔离不足以承担完整安全边界）、网络环境复杂（需同时访问 Internet、模型 API 与内网系统，并提供独立 L3/L4 隔离）、权限控制严格（agent 可调的 API 必须严格授权）、凭证风险高（凭证一旦进入 agent 就可能被读取甚至泄漏）。其落地思路是：以 Kubernetes Agent Sandbox 作为可信执行环境，以 OVN-Kubernetes 构建多租户网络边界，以 Istio Sidecar 配合租户级 Egress Gateway 构建 L7 服务访问管控。

能做什么
一套企业级 Agent Infra 方案：K8s Agent Sandbox 做可信执行、OVN-Kubernetes 做多租户 L3/L4 网络隔离、Istio Sidecar + 租户级 Egress Gateway 做 L7 管控与身份/凭证治理。
解决什么痛点
Agent 会跑未知代码并接触内网与凭证，传统容器隔离扛不住完整安全边界，网络与权限治理缺统一方案。
值不值得
正做 agent 平台、且用 K8s 的团队高度相关，可直接对照自家沙箱/网络/身份设计；偏架构分享，具体实现需自行落地。
