🔥 今日重点

GKE 把网络身份从 Pod label 里摘出来：单集群 3 万沙箱、200k agent 基准下 500 次激活/秒

Google 披露 GKE Dataplane V2 为高密度 agent 沙箱做的改造：前沿实验室已经在要「一百万并发代码执行沙箱」量级，RL 场景下每分钟数千个隔离沙箱起停，而 Cilium/eBPF 的身份模型是「Pod label 映射成一个数字身份」，agent 框架给每个 Pod 打的高基数 label（agent-id、timestamp、claim-uid）会触发逐个身份生成，串行分配时会短暂卡住 Pod 创建，并撞上集群级 65,536 个网络身份的上限。改法是把「识别」与「功能」元数据分开：身份只按参与 selector 匹配的 label 计算，把时间戳、sandbox-name-hash 这类高基数元数据迁到 annotation，再用 label 排除过滤器（如 kube-system 里 cilium-config-emergency-override 配置 !agents.x-k8s.io/sandbox-name-hash）让数据面直接忽略，于是同类 agent 共用同一个 Cilium pod identity，不再线性增长。官方给出的数字是单集群 300 沙箱/秒、亚秒级启动；面向百万级空闲会话的 Agent Substrate 在 200,000 agent 基准中做到 500 次激活/秒、suspend/resume 均低于 500ms，并绕过 K8s 调度器限制。

🔎 新闻要点：需求侧 = 前沿实验室要一百万并发代码执行沙箱，RL 场景每分钟数千沙箱起停；约束 = Cilium/eBPF 身份按 Pod label 生成，集群级上限 65,536，串行分配会暂停 Pod 创建；做法 = 身份只按 selector 相关 label 计算、高基数元数据迁 annotation、用 !agents.x-k8s.io/sandbox-name-hash 等排除过滤器（cilium-config-emergency-override）；结果 = 单集群 300 沙箱/秒、亚秒启动、峰值 3 万沙箱；Agent Substrate = 200,000 agent 基准 500 激活/秒、suspend/resume <500ms，已可在现有 GKE 集群部署。

Gemini 4 Carbon 发布：AA 智能指数 59 分登顶，安全基准 SEC-bench Pro 88.2%

DeepMind 10 月 28 日发布 Gemini 4 Carbon，在 Artificial Analysis Intelligence Index v5.0 上以 59 分排第一，主打网络安全与长程任务：SEC-bench Pro 找漏洞 88.2%、ExploitGym 利用 54.8%、CWE-bench 打补丁 71.0%，WebDev Arena 跳到 1768 分（第 4，+89 elo）。内部团队称它能连续跑数天做大规模代码库与底层系统的根因定位与修补，价格沿用 Argon 的 $2/百万输入、$10/百万输出，缓存输入按输入价 95% 折扣。发布节奏是分阶段：本周先给部分网络防御方，再通过 Fairwind 计划扩到受信伙伴，之后才上开发者与消费级产品面。

能做什么
前沿模型第一次把「找漏洞—利用—打补丁」三段安全基准同时刷到高位（88.2% / 54.8% / 71.0%），并在 WebDev Arena 1768 分；官方强调长程能力，可在同一任务上连续运行数天不放弃死路。
解决什么痛点
安全团队的真实工作不是单轮问答，而是跨仓库的根因定位与补丁验证；Carbon 的定位是把这条长链条交给模型跑完，同时把「生成安全代码」和降低幻觉/伪造率做成内部指标。
值不值得
值得盯的是它的分阶段放开策略与安全基准，而不是榜单本身：做金融量化基础设施的人应关注它能否在受控环境做代码审计与 CVE 复核。限制是当前只给防御方与 Fairwind 伙伴，普通 API 用户拿不到，且基准均为官方口径、缺第三方复现。

GPT-6.1 Terra 上线：$1/$5 定价，Terminal-Bench 4.0 从 21.5% 拉到 50.3%

OpenAI 发布 GPT-6.1 Terra，标准 API 价格较 GPT-5.6 Terra 直接砍半：输入 $1/百万 token、缓存输入 $0.05、输出 $5。官方成绩里最能说明问题的是 Terminal-Bench 4.0：max 档解决 50.3%，而 GPT-5.6 Terra 此前公布的是 21.5%；Agents' Last Exam 上 medium 档比上一代高 15 个百分点、单任务成本约为其三分之一，官方称表现与 GPT-6 Astra 相当而每 token 价格只有后者十分之一。内部高难事实性压测中，低推理强度下错误率从 53.6% 降到 16.7%，max 档 4.3%。Artificial Analysis 综合指数 max 档 48 分，仍排在 Claude Opus 5.5、Kimi K3.1 Pro、Gemini 4 Argon、Meta Muse Wonder 与 GPT-6.1 Sol 之后。

能做什么
把「电脑操作 + 视觉推理」这一档能力的单价压到 $1/$5：原生支持屏幕理解、跨软件协同与写作，OSWorld 2.1、MMMU-Pro 均超过上一代，Terminal-Bench 4.0 从 21.5% 翻到 50.3%。
解决什么痛点
agent 做长任务的成本主要被输出 token 与重试吃掉；错误率从 53.6% 降到 16.7% 意味着同样任务少绕圈，配合缓存输入 95% 折扣，适合高频、低价值的桌面/终端类自动化。
值不值得
对自建 agent 工作流的人是可以直接换的档位：同任务成本约为 Opus 5.5 的九分之一、速度更快，适合做批量终端与 UI 操作。限制是复杂编程与深度推理仍要上 Sol/Astra，且 48 分的综合指数说明它是「性价比档」而非能力上限。

蚂蚁开源 Ling-3.1-flash-1019：base 560B/激活 25B、MIT 许可，AA 指数 44 分

蚂蚁百灵 10 月 28 日开源 Ling-3.1-flash-1019，同时放出基础模型 Ling-3.1-flash-base：混合线性 MoE 架构，总参数约 560B、每 token 激活约 25B，以 BF16 权重 + MIT 许可开放，可继续预训练与后训练。新版在 Artificial Analysis Intelligence Index v4.3.2 拿到 44 分（较上版 +3），复杂知识工作 AA-Briefcase 从约 1400 升到 1524 Elo，流程自动化 AutomationBench-AA 从 62% 升到 68%，CritPt 从 18% 升到 26%。在 8 个领域 47 项 benchmark 中，base 模型有 32 项超过 DeepSeek-V4-Pro-Base 与 MiMo-V2.5-Pro-Base。

能做什么
开源一个面向 Personal Agent 的长程模型族：560B MoE 只激活 25B，MIT 许可可商用改造；1019 版针对多步骤任务与工具调用做了后训练，同系列还有 Ling-3.1-flash-VL 补视觉。
解决什么痛点
个人 agent 需要「围绕一个目标持续工作」，而多数开源中小模型只优化单轮问答；560B/25B 的稀疏比是为了在长序列与单步算力之间取平衡，直接对准跨会话记忆与任务调度这类产品需求。
值不值得
值得关注的是许可与 base 权重：MIT + BF16 意味着可私有化继续训练，适合把内部流程与工具链灌进去做领域适配。限制是 560B 总量即便只激活 25B，自建推理的显存与带宽门槛不低，且 44 分的智能指数仍落后闭源旗舰一档。

「雇智能体」而不是写提示词：170 道题五轮测试才准上线，搭一个 20 分钟、被采用要 8-9 个月

Snowflake 这篇文章把 agent 落地拆成招聘流程：先定「什么任务值得自动化」（音乐科技公司做 AI 生成曲目分类、车企按优先级框架筛用例），再写岗位说明书（能力、职责、谁对产出负责），最后才是数据入职。文中给出的硬数字很扎眼：搭一个 agent 大约 20 分钟，但从分散数据源收集资料并构建嵌入要花好几周；建一个 agent 约四周，让它真正被组织采用要 8-9 个月；一家车企用 170 道题对 agent 做五轮测试，部署标准是「表现要胜过人类，而不是接近人类」。Snowflake 自己的调研里，65% 的企业认为打破 AI 数据孤岛有挑战或非常有挑战，62% 认为让数据达到 AI 可用状态同样困难。组织上正在分化出三种角色——设计者（建流程与 agent）、控制者（监控执行、验证输出）、审计者（高风险流程独立核验），责任最终仍落在人身上。

能做什么
给出一套可照搬的 agent 上线框架：用例筛选 → 岗位说明书（能力/职责/责任人）→ 数据入职（结构化而非堆量）→ 分角色治理（设计者/控制者/审计者）→ 量化验收（如 170 题五轮、必须胜过人类基线）。
解决什么痛点
大多数企业的 agent 停在试点，是因为只做了「提示词 + 工具」，没人回答治理、度量与纠错；文章的判断是差距不在技术而在管理——「我们拥有 agent」和「我们有效雇用了 agent」之间隔的是岗位与考核。
值不值得
对要把 agent 推进生产的团队，这套框架的价值在于验收口径（胜过人类而非接近）与三角色分工，可以直接映射成内部 agent 平台的审批与审计功能。限制是案例匿名、无量化 ROI，且「8-9 个月采用周期」这类数字来自访谈而非统计。

AWS 开源 Strands Decider 2B 与 Strands Box：2B 决策模型 + 内核级策略沙箱

亚马逊云科技开源两个 agent 组件：Strands Decider 2B 是 20 亿参数的「决策专用」模型，以 Qwen3.5-2B 为基座、把语言模型头换成给候选答案打分的指针头，用 rank-16 LoRA 微调，从预定义选项里选而不是生成长文本，覆盖模型路由、工具选择、分类、护栏与上下文管理。官方数据是 RTX 3090 上决策延迟中位 115ms、M3 MacBook 约 153ms，JevBench v19 检查点在 231 项公开任务上准确率 72.3%。Strands Box 处于开发者预览，把 OS 级隔离与开源策略语言 Dogwood 结合，覆盖 shell、Python、MCP 工具、文件系统与网络访问，规则可以写成「读过客户文件后禁止出站 HTTP」这类跨操作约束，且控制逻辑在模型之外，不依赖提示词服从。

能做什么
Decider 2B 把「选哪个工具/走哪条路由」从大模型生成降级成 2B 模型打分，给出决策 + 置信度，本地可跑、权重与训练脚本全开源；Strands Box 在内核强制隔离之上加一层策略语言，按操作参数与历史放行或拒绝。
解决什么痛点
用大模型做路由既贵又慢，还会为了「回答」而编造选项；用小模型做判别能把延迟压到百毫秒级。沙箱侧的痛点是提示词护栏不可验证，策略层把「不能做什么」变成可审计的规则而非叮嘱。
值不值得
两件事都直接可用：Decider 2B 适合嵌进 agent 的 router 环节省 token，Strands Box 的 Dogwood 策略与他关心的「agent 越权」是同一问题。限制是社区已反馈并发请求、Apple Silicon 兼容与冷启动延迟问题，Box 仍是 preview，生产前要自己压测。

Google Agent Skills 像产品一样发版：21k star、170+ skill，每次改动必须带评估证据

Google 公开其 Agent Skills 仓库的工程化流程：两个月内 star 从 15,000 涨到 21,000，收录 Google 内部各团队 170+ 个 skill，并分发到多个 AI 平台。核心立场是「skill 是活产品而不是一次性文档」——文档解释概念给人看，skill 直接左右 agent 的推理循环、工具选择与执行路径，一句位置不当的话就能让 agent 调用非法参数、进死循环或烧 token，所以每次指令改动都是行为变更。落地成三条硬要求：语义化版本（任何行为变更必须显式升版）、确定性自动校验（linter/validator 在人和 AI 评审前先跑）、强制评估证据（每次改动附评估报告，与该 skill 上一版对比，新 skill 则与「没有这个 skill 的 agent」对比）。CI 流水线在提交时即触发，通过后才导出到 GitHub，另有一个 AI review agent 检查 skill 质量。

能做什么
把 skill 仓库做成产品发布流水线：语义化版本 + CI lint/链接检查 + 评估报告（有 skill vs 无 skill、新版本 vs 旧版本）+ AI review agent 审质量，全部在导出到公开仓库前卡住。
解决什么痛点
skill 无法像代码那样靠类型检查兜底，未经评审的一句措辞就可能改变 agent 行为；团队规模一大，人工审 SKILL.md 就失效，必须靠确定性校验 + 评估基线把「行为变更」变成可测的东西。
值不值得
他自己就在维护 skill marketplace，这套门禁可以直接抄：给每个 skill 加版本号，改动必须附「有/无该 skill」的对比证据，AI review 只做二次筛。限制是评估套件本身要成本（要有可重复的任务集与判分），小规模仓库全量套用会偏重，可先只对高频 skill 上强制评估。

Antigravity SDK 支持本地模型：架构师在云、构建者在本地，3400 个 token 只有 95 个上云

谷歌给 Antigravity SDK 加了本地模型支持，把「架构师-构建者」模式搬到混合环境：云端的高上下文 agent 只拿文件名与任务描述做拆解与策略，不接触源码；本地并行跑多个专长 agent 做复现漏洞、改补丁、审查候选补丁、跑回归测试，代码密集阶段全留在设备上。官方演示审计并修补三个有漏洞的 Python 模块，约 3400 个 token 里只有 95 个用于云端规划，其余 97.2% 在本地消耗，且没有源码上传。实现以 LiteRT 跑 Gemma 4 26B A4B 为主，也通过 LocalOpenAIAgentConfig 接 Ollama、LM Studio、vLLM 等 OpenAI 兼容本地推理服务；社区反馈提醒 24GB+ 显存或统一内存是门槛，且「本地占比 97.2%」不等于更快更便宜，应同时看补丁接受率、运行时间与能耗。

能做什么
用两段式编排把敏感代码留在本地：云端 agent 只做规划（文件名+任务描述），本地 agent 执行修补与验证；可接 LiteRT/Gemma 4 26B，也可接 Ollama/LM Studio/vLLM 这类兼容服务，未上传源码。
解决什么痛点
企业想让 agent 改代码，但把源码送云违反数据边界；纯本地又缺长上下文规划能力。架构师-构建者把「想」和「做」分到两侧，用 2.8% 的云 token 换全局规划。
值不值得
对金融量化的代码保密场景是现成范式：规划上云、执行留本地，可量化「上云 token 占比」作为合规指标。限制是本地需 24GB+ 显存/统一内存，演示只覆盖 Python 审计修补，且 97.2% 本地占比不能证明端到端更快更省，需要自己测补丁接受率与实际耗时。

Instagram 把 Android UI 迁到 Compose 改造成「AI 原生」代码库：UI 代码 -50%、每个 agent 会话 token -33%

给注意力头装「安全门」：HoS 把提示注入的 ASR 从 97% 压到 10%

论文提出 Heads of Security（HoS）：不做微调、不改提示词，而是在模型里加一小组可学习的 per-head 注意力门，让每个头自己决定在可信 token 与不可信 token 之间怎么重新分配注意力，从而在架构层实现「指令-数据分离」。在 Llama-3.3-70B-Instruct 与 GPT-OSS-20B 上对比 SecAlign++（微调类 SOTA）与 ASIDE（同为架构类防御）：黑盒 RL-Hammer 攻击对 GPT-OSS-20B 达 97% 攻击成功率、对 SecAlign 85%，对 HoS 只有 10%；白盒攻击 Claudini 经自动搜索强化后，要在 HoS 上达到同等 ASR 需要 3 倍 FLOPs。HoS 在标准选择题基准上保持原始效用，而 SecAlign 与 ASIDE 在 few-shot 设置下会退化。

能做什么
用一组学习到的注意力门在推理时区分可信指令与不可信内容，黑盒攻击 ASR 从 97%/85% 降到 10%，白盒攻击成本提高 3 倍，同时不牺牲基础模型在通用基准上的表现。
解决什么痛点
提示注入的根因是模型把「数据」当「指令」读；提示词防御与微调防御都可被自适应攻击绕过或在 few-shot 下掉点，门控把边界放进注意力分配这一层。
值不值得
对要把 agent 接外部网页/邮件/文档的场景是方向性证据：防御应在架构层而非提示层。限制是需要改模型内部结构并训练门控，只能用开源权重（Llama/GPT-OSS），闭源 API 无法施加，且评测集中在静态攻击集。
