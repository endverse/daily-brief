🔥 今日重点

OpenAI Habitat 第二部分：Cosmos DB 多租户 + Rust 重写，全局读 p50 从 120ms 压到 10ms

Habitat 是 ChatGPT 与 Codex 的在线存储平台，现服务 10 亿+ 周活、近 40 个地域、每秒 7000 万+ 请求、500PB+ 数据。第二部分专讲底层 Azure Cosmos DB：与 Azure 团队做出「共同管理的容器」（co-managed containers）多租户方案——多个租户共享容器但逻辑隔离，配合全局缓存层吸收读放大，再把 Habitat 服务本身从 Python 重写成 Rust 以去掉代理开销。官方口径是全球读 p50 从约 120ms 降到约 10ms（12×），该 Cosmos DB 账户存数十 PB、峰值 2000 万+ QPS；平台只对外暴露受限查询接口，不允许无界查询直达数据库。

🔎 新闻要点：Habitat 规模 = 10 亿+ 周活 / 近 40 地域 / 7000 万+ RPS / 500PB+；Part II 主题 = Cosmos DB 多租户（co-managed containers）+ 全局缓存 + 服务侧 Rust 重写；效果 = 全球读 p50 约 120ms → 约 10ms（12×，2026 年内）；Cosmos DB 账户 = 数十 PB、2000 万+ QPS；设计约束 = 只暴露受限查询 API，禁止无界查询与 SQL 直达，理由是无界查询「便宜好写、昂贵难跑」；全部数字为 OpenAI 自报，无第三方验证。

反向谄媚实验：32 人跟「0–100% 假事实」的助手学科学，置信度再也分不出对错

32 名被试与同一个模型（GPT-5-mini）的 5 个助手学最多 5 个科学主题，每个助手的简报分别有 0/25/50/75/100% 的事实被换成看似合理的假话，且全部以十足把握陈述。104 场测验、1040 个答案显示：总分从 7.4 掉到 2.9（满分 10），被篡改的题目有 60% 选了植入的假答案（未篡改题 11%，OR 12.5）；助手每说一次假话约 65% 会被采纳，被吸收的假事实带着 8.4/10 的高置信，置信度区分对错的 AUROC 从 0.70 掉到随机水平，而任务后的信任评分几乎没动。

能做什么
用受控实验把「人向模型屈服」量出来：固定模型、只改事实正确率与置信表达，再测人答题、置信校准与信任评分；并提出 Human Deference Index 做基线校正。
解决什么痛点
现有谄媚评测几乎只测「模型是否顺着用户」，漏掉了更危险的一侧——用户顺着自信的模型；而产品侧常用置信度做兜底，这里恰好证明置信度会失效。
值不值得
对做 agent 产品的人有直接含义：可靠性要做成逐条 claim 可见，而不是给一个整体置信分；但样本只有 32 人、单一模型，方向可信，数值别外推。

856K 参数的小策略就能改扩散语言模型解码：LLaDA-8B 上拿到最佳精度–NFE 前沿

把监督式 unmasking 策略看成「用教师蒸馏一段解码过程」，分别拆开四个变量：教师标什么算可提交、在哪些状态上模仿、策略能观察到什么、以及 NFE 要降多少才抵得掉策略自身开销。结论是以「与最终输出一致」作标签在低 NFE 下过于宽松，只用隐状态偏弱但与置信度互补，约 10% 的 NFE 降幅即可抵消 7.5M 参数以内策略的开销。改用只接受「留在参考轨迹上」的提交为目标、输入用置信度加隐状态后：LLaDA-8B-Instruct 上 856K 参数策略拿到 GSM8K 最佳精度–NFE 前沿与最高吞吐，MATH-500/HumanEval 中等目标下有竞争力，并能大体迁移到 Dream-7B。

能做什么
给出并行解码里「该提交哪些 token」的可训练判据（轨迹收缩目标），并量化策略开销与 NFE 收益之间的平衡点。
解决什么痛点
扩散语言模型的加速长期依赖手工启发式（置信度阈值），策略化以后没人说清哪一部分在起作用、多小的策略才划算。
值不值得
关注推理加速可以读方法部分；但结论绑 LLaDA/Dream 两个模型族与 GSM8K 类任务，离生产推理栈还有距离。

西班牙 MIR 考试实测 4 个开源模型（8–27B）：三个能进前 600–3000 名，但「弃答」从不划算

按考试自身规则评 8 个年度共 1552 题：三个较大模型若全部作答，排名约在前 600–3000 名，仍有 41–43 个专科可选。放弃作答从不划算——即使最不自信的答案，正确率也高于 25% 的四选一盈亏线；医学微调降低了过度自信但牺牲准确率，且没有改善置信度对正确性的区分能力。另有 13–38% 的正确答案是靠临床上站不住脚的理由排除干扰项，置信度并不反映这一点；去掉或替换题目附带的图像，准确率不变。

能做什么
不只测准确率，还测「知不知道自己会错」（弃答收益）、「对的答案是否因为对的原因」（干扰项排除理由的临床合理性）、以及是否真的用了图。
解决什么痛点
医院想把开源模型跑在自己硬件上，需要的是校准与可解释性而不是考试分数；这篇正好给出三条常被忽略的失败模式。
值不值得
与他的方向关系不大，但「弃答不划算 + 置信度不能用于分诊」这两条对任何要上生产的高风险决策场景都适用。

Hallmark：Together AI 的「反 AI 味」设计 skill，48 个主题 + 真浏览器 lint，一天涨 455 星

这是给 Claude Code / Codex / Cursor / OpenCode 用的设计 skill，做法不是发模板而是发验收：先从 48 个「材料级」主题（纸、字、色、表面、组件、纹理各成一套，并附成品页截图）里抽三个，再按「访问者来干什么」决定页面结构与收尾动作，然后在真实浏览器里 lint 那些一眼机器味的特征——每个标题上都挂 eyebrow、字距拉开的全大写小标签、标题里只染一个词、整页空框或满屏照片、首屏超出视口、每页尾部都塞邮件订阅、表单点了「谢谢」却没真发出去。门禁分三层：Floor（对比度、焦点态、reduced motion、编造事实、手机布局坏）永不放行；Reflex 是模型默认会掉进去的坑，有理由可以记账后越过；Finish 只是工艺细节，不阻塞发布。最后由一个「干净上下文」的 reviewer 拍板，v2 还支持直接指向 URL 或 dev server 自己截图、755 张授权照片，以及 /hallmark redesign 与 /hallmark audit 两个子命令。

能做什么
把审美变成可执行的 lint 规则 + 分层门禁 + 独立上下文复核；主题是材料包而不是配色表，页面结构由任务决定而不是由模板决定。
解决什么痛点
生成式前端最大的问题是同质化（标题 eyebrow、渐变紫、三栏卡片）和自评自过；改 prompt 治不了，得靠外部检查器与硬性 floor。
值不值得
值得抄的是结构不是主题：规则化验收 + 分层门禁 + 换上下文复核，可直接搬到内部的代码规范、文档规范、K8s 清单审查类 skill；48 个前端主题对非设计场景是负担，得裁。

OpenAI 讲 FDE：先把能用的东西塞进用户手里，产品变强后再把自己的定制实现换掉

OpenAI 的 Forward Deployed Engineering 负责人谈这个团队怎么做企业落地：嵌入客户现场，用 LLM 的构建速度先把有价值的东西交付出去，看什么在真实环境里站得住，再把站得住的部分规模化。文中明确的一条原则是顺序——先快、再学、后放大；并直言「让自己变得不必要」是目标之一：产品能力上来之后，可以替换掉大量定制实现而保留已交付的价值。文中举的例子包括帮助农机客户在整个客户旅程里给出相关建议这类场景。

能做什么

解决什么痛点
企业 AI 项目最常见的死法是先做通用平台再找场景，或者交付完一堆定制代码没人维护。
值不值得
与他的工作不直接相关，但「定制探路 → 产品收编 → 删定制」的节奏可以套到内部平台建设上：先给业务做一版，再把它变成平台能力。

cert-manager 1.21.3：摘掉被攻破的 eMudhra 根证书，堵住「能写 status 就能换走私钥」的越权链

v1.21.3 从基础镜像移除被攻破的 emSign ECC Root CA - G3，Go 1.26.10 的 crypto/x509 也开始拒绝经过被攻破中间 CA 的证书链（CVE-2026-111943）。同时修一条权限链：requestmanager 与 issuing 控制器此前只要读到 status.nextPrivateKeySecretName 指向的 Secret 就会复制私钥，于是能写 certificates/status 却读不到 Secret 的主体，可以指定命名空间内任意 Secret，让控制器把它的私钥拷进 spec.secretName；现在只接受带 cert-manager.io/next-private-key 标签且被该 Certificate 拥有的 Secret，keymanager 也不再拿该字段命名下一个私钥。另修 ACME ARI 续期死循环——旧 ARI 窗口会触发反复签发直到撞上 CA 限流。

能做什么
基础镜像去根证书 + 依赖 Go 1.26.10 的 x509 拒绝链；控制器侧把「下一个私钥 Secret」的信任条件收紧为标签 + owner 双重校验；ARI 增加 certID 追踪以重取窗口、打断重复签发。
解决什么痛点
供应链层面，被攻破的公共根会让所有走系统信任库的 TLS 校验失真；集群侧，能改 status 子资源却读不到 Secret 的角色（常见于 CI 或最小权限 operator）原本可以借控制器偷私钥，属于横向提权。
值不值得
只要集群里跑 cert-manager 就该跟，尤其有跨命名空间多租户的；顺带检查是否有 RBAC 允许非管理员写 certificates/status，这条权限现在必须收回。
